## 2. 데이터 분할 및 누수 확인 (CP-02)

- **Train:** 2011-01-01 00:00:00 ~ 2012-05-25 00:00:00 / 12139건 / `cnt` 평균 159.7
- **Validation:** 2012-05-26 00:00:00 ~ 2012-09-11 00:00:00 / 2616건 / `cnt` 평균 281.0
- **Test:** 2012-09-12 00:00:00 ~ 2012-12-31 00:00:00 / 2624건 / `cnt` 평균 235.7
- **시간 순서로 분할한 이유:** 미래의 데이터로 과거를 예측하는 시계열 모순을 방지하고 실제 서비스 환경에서의 일반화 성능을 검증하기 위함
- **`casual + registered == cnt` 확인 결과:** 17,379행 모두 True
- **누수 가능성이 있어 제외한 특성과 이유:** casual, registered > 두 특성 값을 합하면 cnt와 같은 값을 지니게 되며 미래 시점에 알 수 없는 정보이기 때문에 데이터 누수를 유발

**분석:** 세 집합의 `cnt` 평균이 서로 다르다면, 그 차이가 이후 모델 평가에 어떤 영향을 줄지 1~2문장으로 작성합니다.  
데이터의 분포나 시계열적 특성(계절성 및 트렌드)이 집합 간에 균등하게 분할되지 않았음을 의미하기 때문에 검증 및 테스트 단계에서 성능과 신뢰성이 떨어짐.

## 3. 상관관계 및 입력 특성 분석 (CP-02)

- **`temp`와 `cnt`의 상관관계:** 0.398

- **사용한 특성 목록(`FEATURES`):**

(선택 근거는 `adr.md` 의사결정 ①에 작성)

**분석:** 상관관계에서 알게 된 점과 상관계수만으로 특성을 결정할 수 없는 이유를 간단히 작성합니다.  
상관관계 분석을 통해 temp(기온)와 cnt(대여량) 간에 양의 상관관계가 있음을 확인했으나, 상관계수는 선형 관계만을 측정하므로 비선형적 패턴이나 복합적인 상호작용(예: 체감 온도, 시간대별 특성 등)을 온전히 반영하지 못함. 따라서 단순 상관계수 절대값의 크기만으로 특성의 중요도를 단정하여 입력 특성을 결정할 수 없음

## 4. 특성공학 및 전처리 (CP-03)

- **생성한 특성:** `is_commute_hour`
- **특성 생성 조건:** 
시간(hr)이 출퇴근 피크 시간대(예: 7~9시, 17~19시)에 해당하는지 여부에 따라 1 또는 0으로 생성
- **범주형 특성 처리:** 
"season", "yr", "mnth", "hr", "weekday", "weathersit" One-Hot Encoding 적용
- **수치형 특성 처리:** 
"temp", "atemp", "hum", "windspeed" StandardScaler를 이용한 표준화 적용
- **이진 특성 처리:** 
"holiday", "workingday", "is_commute_hour" passthrough를 통해 변형 없이 그대로 통과
- **Train 전처리 전후 Shape:** (12139, 13) → (12139, 60)
- **Validation에 적용한 변환 기준:** 
Train 데이터로 학습된 전처리기(preprocessor.fit())를 바탕으로 동일하게 변환(transform()) 적용
