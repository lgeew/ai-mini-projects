## 1. 데이터 탐색 및 클래스 분포 (CP-01)

- **데이터 크기:** 12330행, 18열
- **결측값 및 중복 행:** 125 
(중복 행을 삭제하지 않은 이유: 세션 데이터 특성상 완전히 동일한 행동 기록(로그)이 우연히 중복으로 존재할 수 있으며, 데이터 손실을 방지하고 원본 분포를 유지하기 위함.)
- **수치형 특성 분포의 특징(`ProductRelated`, `PageValues` 등):** 
대부분의 데이터가 0이나 매우 낮은 구간에 집중되어 있고, 일부 세션만 값이 매우 높게 나타나는 오른쪽으로 긴 꼬리를 갖는 비대칭 분포 형태를 보임.
- **구매(`Revenue=1`) 건수와 비율:** 1,908건 / 15.47%
- **미구매(`Revenue=0`) 건수와 비율:** 10,422건 / 84.53%

**분석:** 모두 미구매로 예측했을 때 Accuracy가 약 84.53%인 이유와 이 수치만으로 평가하기 어려운 점을 작성합니다.  
모두 미구매로 예측할 경우 정확도(Accuracy)가 약 84.5%에 달하지만, 실제 데이터가 미구매 쪽으로 극심하게 치우친 클래스 불균형(Class Imbalance) 상태이기 때문에 단순 정확도만으로는 모델의 성능을 제대로 평가하기 어려움.

## 2. 계층화 데이터 분할 (CP-02)

- **Train:** 8630건 / 구매 비율 15.48%
- **Validation:** 1850건 / 구매 비율 15.46%
- **Test:** 1850건 / 구매 비율 15.46%
- **`stratify`를 적용한 이유:** 
전체 데이터의 구매/미구매 비율(약 15.5%)이 훈련셋과 검증셋에도 똑같이 유지되도록 하여, 한쪽으로 데이터가 치우치는 것을 방지하기 위함.
- **1일차 회귀의 날짜 순서 분할과 다른 이유:** 
앞선 자전거 대여량 예측은 시간에 따른 흐름(시계열)이 중요해 순서대로 잘랐지만, 쇼핑몰 방문 세션 데이터는 시간 순서보다 방문객들의 구매 성향 비율을 골고루 나누는 것이 모델 학습에 더 유리하기 때문.

**분석:** Train·Validation·Test의 구매 비율이 유사한지 확인하고 의미를 1~2문장으로 작성합니다.  
Train과 Validation 세트 모두 구매 비율이 약 15.5%로 동일하게 유지되어, 편향 없는 공정한 학습 및 검증 환경이 구축되었음을 확인함.

## 3. 구매 여부와 관련된 특성 분석 (CP-02)

- **방문자 유형(`VisitorType`)별 구매율:** 
Returning_Visitor 0.1395 / New_Visitor 0.2521 / Other 0.1587
- **구매율이 가장 높은 방문자 유형:** New_Visitor
- **구매·미구매 세션의 `ProductRelated` 중앙값:** 
미구매 16.0 / 구매 29.0
- **구매·미구매 세션의 `ProductRelated_Duration` 중앙값:** 
미구매 517.5 / 구매 1069.6
- **구매·미구매 세션의 `PageValues` 중앙값:** 
미구매 0.0 / 구매 17.5
- **구매·미구매 세션의 `ExitRates` 중앙값:** 
미구매 0.029 / 구매 0.015
- **특성 분석을 Train 데이터에서 수행한 이유:** 
Validation이나 Test 데이터의 정보가 분석 과정에 미리 유출되어 모델 학습에 악영향을 미치는 데이터 누수(Data Leakage)를 방지하고, 모델 검증의 객관성을 유지하기 위함.

**분석:** 구매 여부와 관련된 특성에서 관찰한 점과 `PageValues`의 예측 시점상 한계를 작성합니다.  
PageValues 등의 지표가 구매 여부를 판단하는 데 매우 강력한 특성이지만, 이 지표들은 실제 구매가 일어나는 과정과 밀접하게 연동되어 있어 실제 서비스 운영 시 미래의 정보가 포함될 수 있는 예측 시점상의 한계가 존재함.

## 4. 데이터 전처리 및 PyTorch 입력 준비 (CP-03)

- **범주형 특성(One-Hot 인코딩):** 
Month, OperatingSystems, Browser, Region, TrafficType, VisitorType
- **수치형 특성(표준화):** 
Administrative, Administrative_Duration, Informational, Informational_Duration, ProductRelated, ProductRelated_Duration, BounceRates, ExitRates, PageValues, SpecialDay
- **이진 특성(변환 없이 사용):** 
Weekend
- **숫자로 표현된 코드값(`OperatingSystems`, `Browser` 등)을 범주형으로 처리한 이유:** 
숫자의 크기(크다/작다)가 순서나 가중치를 의미하는 것이 아니라 단순한 '카테고리(분류)'를 나타내기 때문에, 모델이 이를 잘못된 크기 관계로 오해하지 않고 독립된 범주로 인식하도록 하기 위함.
- **`handle_unknown="ignore"`를 설정한 이유:** 
Train 데이터에 없던 새로운 범주(카테고리) 값이 Validation이나 Test 데이터에 등장하더라도 에러를 발생시키지 않고 무시하여 안정적으로 처리하기 위함.
- **Train 전처리 전후 Shape:** (8630, 17) → (8630, 73)
- **Validation에 적용한 변환 기준:** (1850, 73)
- **PyTorch 입력·타깃 Tensor의 자료형 및 Shape:** 
torch.Size([8630, 73]) torch.Size([8630, 1])
- **`DataLoader` 배치 크기와 배치 수:** 256 / 34

**분석:** 신경망 입력을 `float32` Tensor로 준비하고 미니배치를 만드는 이유를 1~2문장으로 작성합니다.  
PyTorch 연산 최적화와 가중치 계산의 효율성을 위해 표준 데이터 타입인 float32 Tensor로 변환하였으며, 대용량 데이터를 한 번에 메모리에 올리지 않고 미니배치(Batch) 단위로 나누어 학습함으로써 학습 안정성과 속도를 높이기 위함.
